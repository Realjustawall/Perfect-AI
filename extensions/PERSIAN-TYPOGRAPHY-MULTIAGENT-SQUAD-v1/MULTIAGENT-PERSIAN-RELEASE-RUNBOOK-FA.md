# Runbook نهایی تیم چندایجنتی و فونت فارسی

## مرحلهٔ صفر: انتخاب حالت اجرا
1. بررسی کن محیط واقعاً از اجرای چندایجنتی/ساب‌اجنت پشتیبانی می‌کند یا خیر.
2. اگر پشتیبانی دارد، از پروفایل‌های `agents/` استفاده کن و هماهنگ‌کننده مالک جمع‌بندی نهایی بماند.
3. اگر پشتیبانی ندارد، نقش‌ها را به‌ترتیب در یک ایجنت اجرا کن و ادعای اجرای موازی واقعی نداشته باش.
4. نصب MCP، اجرای نصب‌کننده یا تغییر تنظیمات حساب/IDE فقط با دسترسی و مجوز لازم انجام شود.

## تقسیم کار پیشنهادی
- Orchestrator: هدف، معیار پذیرش، Task Graph و مالکیت فایل‌ها.
- Research: مستندات رسمی، نسخه‌ها، مجوزها و شواهد.
- Architecture: مرزهای کامپوننت و وابستگی‌ها.
- Visual Design: مشخصات بصری و حالت‌های responsive.
- Frontend: پیاده‌سازی در محدودهٔ فایل‌های تخصیص‌یافته.
- Isometric/Motion: Pointer، SVG، هندسه و چرخهٔ عمر انیمیشن.
- Persian Typography: انتخاب فونت، RTL، اعداد و آزمون حروف.
- Accessibility: صفحه‌کلید، Focus، کنتراست، Touch و Reduced Motion.
- Performance: Render، layout shift، bundle و فریم‌ها.
- QA: تست‌های unit/browser/visual.
- License/Security: مجوز فایل فونت، وابستگی و منشأ بسته‌ها.
- Code Review: بررسی مستقل diff.
- Release Auditor: شمارش، مسیرهای افزوده، حفظ آرشیو و گزارش صادقانه.

## قرارداد تحویل نقش
هر ایجنت باید اعلام کند: محدودهٔ وظیفه؛ فایل‌های خوانده‌شده و تغییرکرده؛ تصمیم‌ها؛ منابع؛ تست واقعاً اجراشده و نتیجه؛ ریسک‌ها و موارد انجام‌نشده؛ مسئول بعدی. هر فایل فقط یک نویسندهٔ فعال دارد. ادغام تغییرات سریالی و پس از هر ادغام تست مرتبط تکرار می‌شود.

## دروازهٔ اجباری فونت فارسی
1. تشخیص حضور فارسی در UI، route، فرم یا locale.
2. انتخاب پیش‌فرض Vazirmatn یا جایگزین کاتالوگ با دلیل.
3. بررسی مجوز دقیق asset/version و ثبت لینک منبع.
4. بارگذاری واقعی فایل فونت و بررسی network/local asset و computed font-family.
5. تست `پ چ ژ گ ک ی آ ؤ ئ ۰۱۲۳۴۵۶۷۸۹` و جملهٔ نمونه.
6. بررسی شکل‌دهی، اعداد، punctuation، متن RTL همراه URL/کد LTR، موبایل و دسکتاپ.
7. اگر هر مرحلهٔ اصلی شکست خورد یا اجرا نشد، نتیجه `BLOCKED` یا `NOT RUN` است؛ نه PASS.

## دروازهٔ انتشار افزایشی
1. ثبت فهرست مسیرهای پایه قبل از تغییر.
2. استفاده از مسیرهای جدید یکتا؛ در این وظیفه هیچ فایل قبلی حذف یا بازنویسی نشود.
3. اعتبارسنجی JSON، UTF-8 و ساختار ZIP.
4. مقایسهٔ مسیر و size/CRC تمام ورودی‌های پایه با خروجی؛ استفاده از hash رمزنگاری در صورت نیاز به سطح بالاتر اثبات.
5. گزارش آمار جداگانه برای کل فایل‌های `SKILL.md`، شناسه‌های یکتا، تعداد Skillهای جدید و تعداد ورودی‌های ZIP.
6. تحویل ZIP، فهرست Skillها، گزارش ممیزی و ذکر دقیق محدودیت‌های بررسی.

## تصمیم موتور انیمیشن
اول قابلیت‌های موجود Isometric را بررسی کن. برای transition ساده CSS، برای حرکت تعاملی React Motion، و برای تایم‌لاین واقعاً پیچیده GSAP را برگزین. بیش از یک موتور برای یک رفتار، بدون دلیل مستند اضافه نکن. پاک‌سازی هنگام unmount، pointercancel، تعامل لمسی، کاهش حرکت و ریسپانسیو را آزمایش کن.
